本期 PROMPT
🔬 两份文档逐条审
Document Comparison - Deep Review
✨ 每节都给个状态 → 义务和 SLA 一条条过筛 → 按风险高低排好队 🔬
大多数时候，你就是想知道『这版跟上版差在哪』——那用 P099 就够了，快、干净、看完就走人。

可有些文档不能只看『哪儿不一样』。供应商把合同改了一版发回来、Tier-1 的规格书要对着 OEM 需求核、SOP 上线前得验 SLA 和合规条款——这种时候真正会出事的不是『措辞换了』，而是某一条义务被悄悄抹掉了、SLA 从 99.9% 滑到 99.5%、终止条款里多了一个对方可以单方面退出的口子。这些东西全藏在『两边都有』的章节里，光靠核对有没有永远捞不出来。

这个版本补了四道关卡。第一，章节状态从『在 A／在 B／两边都有』升级成 Present／Missing／Modified——改动过的章节自己会跳出来，不用逐字啃差异栏才发现。第二，它不再让模型自己拿捏什么叫『实质差异』，而是给一张点名清单：矛盾、冲突、新增或删除的义务、要求、约束、SLA、终止条款、合规声明。第三，禁止推断的范围从『别从排版猜含义』扩大到别推断意图和商业理由，并且白纸黑字禁止概括或改写——条款一被概括，法律精确度就没了。第四，重要性从两档改成 Critical → Medium → Minor 三档，中间地带不再被压平。

代价是输出更长、跑得更久。所以按情况挑：日常版本对照用 P099，牵涉义务和风险的文件，用这一份。
  📋 提示词模板（简体中文版）
🔬 本周 Prompt（先把两份文档传上去，再粘这段）

分析并系统化比较文档 A 与文档 B。

说明：
判断每一份文档的类型（合同、技术规格、政策、报告）。
从每一份文档中提取明确的章节和标题。
只比较明确写出来的文字内容。不要推断意图、含义或商业理由。
忽略排版格式上的差异。
对每一个章节，判定：Present（存在）／ Missing（缺失）／ Modified（已修改）。
标出实质差异，包括矛盾、冲突，以及新增或删除的义务、要求、约束、SLA、终止条款或合规声明。
若某处差异不清楚或有歧义，标记：『Requires human review。』

输出格式：结构化表格，列为：章节 | 文档 A 状态 | 文档 B 状态 | 主要差异

约束：
－ 严格只看明确写出来的文字。
－ 不要概括或改写文档内容。
－ 按重要性排序：Critical → Medium → Minor。

可在：Copilot Chat（Work）或 Word 中的 Copilot 使用。
  📋 Prompt Template (English)
🔬 Prompt of the Week (upload both documents first, then paste)

Analyze and systematically compare Document A and Document B.

Instructions:
Identify the document type for each (contract, technical specification, policy, report).
Extract explicit sections and headings from each document.
Compare explicit text content only. Do not infer intent, meaning, or business rationale.
Ignore formatting differences.
For each section, determine: Present / Missing / Modified.
Highlight substantive differences, including contradictions, conflicts, new or removed obligations, requirements, constraints, SLAs, termination terms, or compliance statements.
If a difference is unclear or ambiguous, flag: "Requires human review."

Output format: Structured table with columns: Section | Doc A Status | Doc B Status | Key Differences

Constraints:
– Focus strictly on explicit text.
– Do not summarize or rewrite documents.
– Rank findings by importance: Critical → Medium → Minor.

Try it in: Copilot Chat – Work, or Copilot in Word.
💡 使用技巧
1. 🪶 只想知道改了哪儿？用 P099 就行 — 这份为了盘点义务和风险，输出更长、跑得更久。单纯的版本对照（演示文稿、报告、规格草稿）用 P099 更省事。
2. 🎯 先把你的红线交代清楚 — 补一句『重点盯付款条件、责任上限和数据保护条款』，三档排序就能贴着你的实际风险来。
3. 🔍 优先看 Modified 和『需人工复核』 — 前者说明章节还在但内容被动过，后者是它明说自己判不了；风险最高的条款基本都落在这两类里。

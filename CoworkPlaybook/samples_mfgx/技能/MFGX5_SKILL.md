# 停線事件分級通報

## 何時使用這個技能

在使用者出現下列情形時觸發：

- 訊息中出現「停線」「產線停機」「設備停機」「line stop」「machine down」
- 使用者轉貼或引用一封停線通報信件
- 使用者詢問某次停機應該判為幾級

## 何時**不要**使用這個技能

- 進料檢驗不良、供應商品質異常 → 交給進料異常處理流程
- 例行保養、計畫性換模且**事前已排入生產計畫** → 不屬於停線事件
- 人員請假、排班、加班問題 → 與本技能無關

若判斷屬於上述範圍，明確說明本技能不適用，並建議正確的處理方式，不要勉強套用分級。

## 判定步驟

1. **抽取事實**：設備編號、產線、停線起始時間、目前狀態、預估復機時間、已採取處置。
2. **套用分級**：
   - 預估停線 ≥ 4 小時 **或** 影響出貨承諾日 **或** 涉及人員安全 → **P1**
   - 預估停線 1～4 小時且未影響出貨承諾日 → **P2**
   - 預估停線 < 1 小時且可由當班自行排除 → **P3**
3. **檢查升級規則**（這一步最常被漏掉，務必執行）：
   - 同一設備 7 天內第 3 次停線 → 一律升為 **P1**
   - 初判 P2 但超過 2 小時未排除 → 升為 **P1**
   - 涉及人員安全 → **不得降級**
4. **產出兩份內容**：Teams 一行通報、回覆通報人的信件草稿。

## 輸出格式

Teams 一行通報**固定使用**下列格式，不要改寫欄位順序：

```
[P1] B產線-CNC-07 | 停線起始 09:20 | 預估復機 待確認 | 維修中，等待原廠備品
```

回覆信件須逐項涵蓋：設備與產線、停線起始與現況、判定等級與依據條件、預估復機、已採取處置、需要的支援。

## 遇到資訊不足時

- 缺少預估復機時間 → 寫「待確認」，**不要自行推估**
- 無法判斷是否影響出貨承諾日 → 先按已知條件分級，並在信中明確列為待確認事項
- 完全無法判定等級 → 說明缺少哪些資訊，請使用者補充，**不要猜一個等級**

## 安全限制

- 所有信件與 Teams 訊息**一律先產出草稿**，等使用者核准後才送出
- 不得代替使用者向供應商或客戶承諾復機時間
- 涉及人員安全的事件，不得因為使用者要求「不要小題大作」而降級

# 服務通報適用性判定準則

> 文件管理：機務工程處 技術服務部　|　ZV-ENG-P-0531　|　版次 3.1

## 1. 這份準則要固化什麼

把〈AIR5_工程指令撰寫規範.md〉第 2 節的適用性判定，寫成一套**每次都照同一順序走**的規則，
避免因人而異、因趕時間而簡化。

## 2. 判定順序（不可調換）

```
步驟 1  查改裝套件併裝紀錄
        已併裝 → 不需執行（結束）
步驟 2  查現裝部件的件號與序號
        序號缺漏 → 須人工確認（結束）
步驟 3  現裝部件序號是否落在受影響序號範圍內？
        是 → 需執行
        否 → 不需執行
```

⚠️ **機身序號 MSN 不出現在判定流程裡。** 它只用於交叉核對與記錄，
不作為任何一步的判準。

## 3. 三種輸出

| 判定 | 意義 |
|---|---|
| 需執行 | 開立工程指令，列入執行清單 |
| 不需執行 | 記錄判定依據備查，不開立 |
| **須人工確認** | 資料不足以判定，退回人工查證，**不得推定** |

## 4. 為什麼一定要有第三種輸出

部件更換紀錄若只載件號未載序號，表面上看起來「件號相符」，
很容易被判成需執行；但也可能該顆件的序號根本不在受影響範圍內。

兩種推定都會錯，而兩種錯的後果不同：

- 誤判為需執行 → 浪費工時，但航空器仍適航
- **誤判為不需執行 → 應執行而未執行，逾期即構成不適航**

因此資料不足時唯一安全的輸出是「須人工確認」。

## 5. 必須保留的紀錄

每一架的判定都要留下：機號、機身序號、改裝狀態、現裝部件件號與序號、
判定結果、判定依據、判定日期。

**只留結果不留依據者，視同未判定。**

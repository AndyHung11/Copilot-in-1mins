# 服务通告适用性判定准则

> 文件管理：机务工程部 技术服务室　|　ZV-ENG-P-0531　|　版次 3.1

## 1. 这份准则要固化什么

把《AIR5_工程指令编写规范.md》第 2 节的适用性判定，写成一套**每次都按同一顺序走**的规则，
免得因人而异、赶时间就简化。

## 2. 判定顺序（不可调换）

```
步骤 1  查改装套件并装记录
        已并装 → 不需执行（结束）
步骤 2  查现装部件的件号和序号
        序号缺失 → 须人工确认（结束）
步骤 3  现装部件序号是否落在受影响序号范围内？
        是 → 需执行
        否 → 不需执行
```

⚠️ **机身序号 MSN 不出现在判定流程里。** 它只用于交叉核对和记录，
不作为任何一步的判准。

## 3. 三种输出

| 判定 | 含义 |
|---|---|
| 需执行 | 开立工程指令，列入执行清单 |
| 不需执行 | 记录判定依据备查，不开立 |
| **须人工确认** | 资料不足以判定，退回人工核实，**不得推定** |

## 4. 为什么一定要有第三种输出

部件更换记录要是只载件号没载序号，表面上看“件号对得上”，
很容易被判成需执行；但也有可能这个件的序号根本不在受影响范围内。

两种推定都会错，而两种错的后果不一样：

- 误判为需执行 → 浪费工时，但航空器仍然适航
- **误判为不需执行 → 该执行而没执行，逾期就构成不适航**

所以资料不足时，唯一安全的输出是“须人工确认”。

## 5. 必须保留的记录

每一架的判定都要留下：机号、机身序号、改装状态、现装部件件号和序号、
判定结果、判定依据、判定日期。

**只留结果不留依据的，视同没判定。**

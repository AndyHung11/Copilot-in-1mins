# 技能衝突對照表（TEL5 用）

> 這份表的用途：示範**三個技能搶同一批請求**時，怎麼靠描述把邊界寫清楚。
> 建立技能時把這張表交給 Cowork，請它據此寫出彼此的排除條款。

## 一、三個技能的重疊區

| | SLA 判定技能 | 消費者申訴回覆技能 | 個資外洩通報技能 |
|---|---|---|---|
| 觸發語 | SLA、專線、違約金 | 申訴、客訴、NCC | 外洩、資安事件、通報 |
| 對象 | 企業客戶 | 個人用戶 | 主管機關／當事人 |
| 產出 | 賠償通知 | 回覆函 | 通報書 |

### ⚠️ 會打架的請求（實際測試用）

| 使用者說 | 應該由誰處理 | 為什麼容易搶錯 |
|---|---|---|
| 「這個月的專線中斷要賠多少？」 | SLA 判定 | 明確，不易錯 |
| 「客戶投訴專線一直斷，幫我回覆」 | **消費者申訴回覆**（但若對方是企業客戶且要談賠償金額 → SLA 判定） | 同時有「投訴」與「專線」 |
| 「專線中斷害客戶資料傳輸中斷，要通報嗎？」 | **個資外洩通報** | 有「專線中斷」但重點是通報義務 |
| 「幫我處理這個月所有客戶問題」 | **應該反問澄清**，不該擅自挑一個 | 三個技能都沾得上邊 |

## 二、寫排除條款的三個原則

1. **正面說明何時用，反面明確列出何時不用**
   只寫「用於 SLA 判定」不夠，要寫「Do NOT use for 消費者申訴（改用 X 技能）」

2. **排除條款要指名接手的技能**
   只說「不處理個資事件」會讓請求無人接手；
   要寫「→ use the 個資外洩通報 skill instead」，形成明確委派

3. **混合請求要有處理規則**
   請求同時涉及兩個領域時，技能應**只處理自己該處理的部分**，
   並明確說明哪些被排除、該由誰接手 —— 而不是全做或全不做

## 三、驗收方式

建立完三個技能後，開新工作階段依序丟出上表四個請求，確認：

- [ ] 前三個請求各自由正確的技能接手
- [ ] 第四個模糊請求會**反問澄清**，而不是擅自挑一個技能執行
- [ ] 混合請求時，技能會說明哪些部分不屬於自己的範圍

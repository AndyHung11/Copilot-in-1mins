# S5 触发测试邮件（第 4 步用）

> **用途**：测试「事件触发任务」有没有真的启动。
> **做法**：把下面的主题和正文，用你自己的邮箱**发给你自己**，然后不要下任何指令，等它自己动。

---

## 主题（照抄，关键词必须包含「周报素材」）

```
周报素材 — 智慧作战室实施项目 第 7 周
```

## 正文（照抄，或者换成你自己的工作记录）

```
- 周一（2026/07/13）：合规说明文档写完初稿，法务看过，要补一段数据保留期限的说明。
- 周二（2026/07/14）：预测分析模块开工，先做需求盘点，客户想要的其实跟原本 SOW 有出入，要拉一次会确认范围。
- 周三（2026/07/15）：SSO 集成终于排上了，对方 AD 团队回复可以在 7/22 那周做。拖了两周总算有进展。
- 周四（2026/07/16）：dashboard 上线后第一次真实流量测试，峰值 180 并发没问题，响应时间保持在 3 秒内。
- 周五（2026/07/17）：weekly sync，陈 PM 反馈她的领导想看「跨月趋势」，这个原本不在范围内，我先说要评估。
- 卡住的事：预测分析的范围认知有出入，需要下周开会理清，不然做出来会白干。
- 预算：累计约 ¥37 万，仍在预算内。
- 下周要做：合规文档定稿、预测分析范围确认会议、准备 SSO 集成。
```

---

## 为什么要用这份，而不是把第 6 周那份再贴一次

第 6 周的记录你在第 3 步已经用过了。如果触发测试又贴同一份，
你**分不出来周报是「刚才那次留下的」还是「这次自动生成的」**。
换一份内容，看到「第 7 周」才能确定它真的重新跑了一次。

## 这份里面刻意埋的东西

| 埋点 | 用意 |
|------|------|
| 「拖了两周总算有进展」 | 内部抱怨，**不该出现在对外周报里** |
| 「做出来会白干」 | 同上，语气负面 |
| 范围认知有出入 | 应该被归到「风险与问题」段落 |
| 领导想看跨月趋势 | 应该被归到「需客户配合事项」或风险 |
| 预算 ¥37 万 / 67 万 | 数字要正确带出来，不能写错 |

收到自动生成的周报后，用这张表对一遍 —— 这比看它「有没有跑」更重要。

## ⚠️ 练习完记得

到<b>自动化</b>页把这个事件触发任务设为**暂停**，
否则以后任何主题含「周报素材」的邮件都会触发它。

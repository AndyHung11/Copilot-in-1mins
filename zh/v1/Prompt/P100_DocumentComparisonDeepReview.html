本 期 PROMPT
🔬 兩份文件深度審查比對
Document Comparison - Deep Review
✨ 逐節標 Present／Missing／Modified → 盤點義務與 SLA → 三級風險排序 🔬
多數時候，你只是想知道「這版跟上一版差在哪」—— 那用 P099 就夠了，快、乾淨、看完就走。

但有些文件不能只看「哪裡不一樣」。供應商把合約改了一版寄回來、Tier-1 的規格書要對照 OEM 需求、SOP 上線前要驗 SLA 與法遵條款 —— 這時真正會出事的不是「文字換了」，而是某一條義務被悄悄拿掉了、SLA 從 99.9% 變成 99.5%、終止條款多了一個對方可片面解約的情境。這些東西藏在「兩邊都有」的章節裡，光看存在與否永遠掃不出來。

這個版本補上四道關卡。第一，章節狀態從「在 A／在 B／兩邊都有」升級為 Present／Missing／Modified —— 改過的章節自己會跳出來，不必逐字讀差異欄才發現。第二，它不再讓模型自由心證什麼叫「實質差異」，而是給一張點名清單：矛盾、衝突、新增或移除的義務、要求、限制、SLA、終止條款、法遵聲明。第三，禁止推論的範圍從「不要從排版推論語意」擴大到不要推論意圖與商業理由，並且明文禁止摘要或改寫 —— 條款一被摘要，法律精確度就毀了。第四，重要性從兩級改為 Critical → Medium → Minor 三級，中間地帶不再被壓扁。

代價是輸出更長、跑得更久。所以請按情況挑：日常版本對照用 P099，牽涉責任與風險的文件，用這一份。
  📋 提示詞範本（繁體中文版）
🔬 本週 Prompt（先上傳兩份文件，再貼上）

分析並系統化比較文件 A 與文件 B。

指示：
辨識每一份文件的類型（合約、技術規格、政策、報告）。
從每一份文件中擷取明確的章節與標題。
僅比較明確存在的文字內容。不要推論意圖、語意或商業理由。
忽略排版格式上的差異。
針對每一個章節，判定：Present（存在）／ Missing（缺少）／ Modified（已修改）。
標示實質差異，包括矛盾、衝突，以及新增或移除的義務、要求、限制、SLA、終止條款或法遵聲明。
若某項差異不清楚或有歧義，標記：「Requires human review。」

輸出格式：結構化表格，欄位為：章節 | 文件 A 狀態 | 文件 B 狀態 | 主要差異

限制：
－ 嚴格聚焦於明確存在的文字。
－ 不要摘要或改寫文件內容。
－ 依重要性排序：Critical → Medium → Minor。

可在：Copilot Chat（Work）或 Word 中的 Copilot 使用。
  📋 Prompt Template (English)
🔬 Prompt of the Week (upload both documents first, then paste)

Analyze and systematically compare Document A and Document B.

Instructions:
Identify the document type for each (contract, technical specification, policy, report).
Extract explicit sections and headings from each document.
Compare explicit text content only. Do not infer intent, meaning, or business rationale.
Ignore formatting differences.
For each section, determine: Present / Missing / Modified.
Highlight substantive differences, including contradictions, conflicts, new or removed obligations, requirements, constraints, SLAs, termination terms, or compliance statements.
If a difference is unclear or ambiguous, flag: "Requires human review."

Output format: Structured table with columns: Section | Doc A Status | Doc B Status | Key Differences

Constraints:
– Focus strictly on explicit text.
– Do not summarize or rewrite documents.
– Rank findings by importance: Critical → Medium → Minor.

Try it in: Copilot Chat – Work, or Copilot in Word.
💡 使用小撇步
1. 🪶 只想知道改哪裡？用 P099 就好 — 這份為了盤點責任與風險，輸出較長、跑得較久。單純的版本對照（簡報、報告、規格草稿）用 P099 更省時。
2. 🎯 把你的紅線先講明 — 補一句「特別注意付款條件、責任上限與資料保護條款」，三級排序會更貼近你的實務風險判斷。
3. 🔍 Modified 與「需人工複核」優先看 — 前者代表章節還在但內容被動過，後者是它明說自己判不了；風險最高的條文通常就落在這兩類。
